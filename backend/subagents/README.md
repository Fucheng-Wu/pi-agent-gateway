# 自定义子 agent

每个项目子 agent 使用一个独立目录：

```text
backend/subagents/
└── reviewer/
    ├── agent.md
    └── tools.ts
```

`agent.md` 的正文是该子 agent 的系统提示，frontmatter 支持：

- `name`：调用时使用的唯一 ID。
- `display_name`、`description`：设置页展示信息。
- `tools`：允许的内置或扩展工具名；支持 Pi 的工具匹配模式。
- `skills`：只加载列出的技能名；`["*"]` 表示加载全部已发现技能。
- `extensions`：相对于 `agent.md` 的 Pi 扩展模块。扩展必须位于该子 agent 目录中，可以注册专属工具。
- `permissions`：可选的单行 JSON 权限规则数组（action/resource/effect）；子代理执行时同时受主代理及所有祖先的权限、工具范围约束，不能通过自身 allow 放宽祖先限制。

复制 `_template` 目录，改名后把 `agent.md.example` 改成 `agent.md`。如果不需要专属工具，删除 `extensions` 并移除 `tools` 中对应的工具名即可。

`settings.json` 控制总开关、并发上限和禁用角色。设置页修改后也会写回此文件。

主代理配置见 [primary-agents](../primary-agents/README.md)。其中 `mode: all` 的角色同时可作为子代理调用。需要确认的子代理操作在主任务所属浏览器弹出确认，显示具体角色；取消主任务会一并取消审批和正在执行的子任务。

## 协作工具

启用子代理后，主代理与通过 `spawn_agent` 创建的所有团队成员共享以下协作工具：

| 工具 | 用途 |
| --- | --- |
| `spawn_agent({profile, task, name?, task_name?, fork_context?})` | 后台创建自己的子代理，立即返回 ID、完整路径和父代理 ID |
| `send_message({agent_id, message})` | 向同团队任何代理发消息，包括父代理、同伴及 `/root`；不启动空闲代理 |
| `followup_task({agent_id, task})` | 给自己的后代追加任务；忙碌时排队，已完成或中断时沿用历史继续 |
| `list_agents({})` | 返回自己的身份以及整个团队的代理路径、父子关系和状态 |
| `wait_agent({timeout_ms?})` | 等待并读取自己的消息箱；包含同伴消息和直属子代理的最终结果，读取后消费 |
| `wait_agents({agent_ids, timeout_ms?})` | 任意一个指定代理完成即返回；默认等 30 秒，最多 60 秒，0 表示立即查看；超时不会停止工作 |
| `interrupt_agent({agent_id})` | 中断自己的后代及其子树，保留上下文供继续执行 |
| `close_agent({agent_id})` | 停止并释放自己的后代及其子树，历史保留，关闭后不能续跑 |

主代理还保留 `followup_agent`、`resume_agent` 两个追加任务的兼容别名，以及旧的 `Agent({profile, task})` 一次性委派入口。旧 `Agent` 的子会话不加入团队，不接收团队协作工具；需要同伴沟通或嵌套委派时使用 `spawn_agent`。

`fork_context` 默认关闭；开启时把启动时调用者的消息和工具记录作为背景快照提供给子代理。各代理共享工作目录，应在任务说明中划分负责的文件，避免并行覆盖。

## 团队身份与通信

每个主会话有独立团队，根地址是 `/root`，后代地址例如 `/root/backend/tester`。`task_name` 指定父代理下唯一的路径名称；省略时由角色或显示名自动生成。工具的 `agent_id` 接受 UUID、完整路径，或相对于调用者的子路径（例如后端代理用 `tester` 定位自己的测试子代理）。跨分支通信请使用完整路径。

消息的发送者由运行时绑定，不能通过工具参数冒充。创建关系形成树，消息可以跨分支。任何成员可以向同团队成员发送消息；追加任务、中断、关闭仅允许作用于自己的后代。主代理因此可以管理整个团队。同伴不能接管或终止彼此，不能等待自身或祖先结束，其他主会话的代理 ID 也不可访问。

例如主代理创建 `/root/backend` 与 `/root/frontend`，后端代理再创建 `/root/backend/tester`；后端可直接用 `send_message({agent_id: "/root/frontend", message: "POST /login 返回 token"})` 分享接口约定，测试代理也可向前端反馈发现。

`send_message` 给运行中的代理注入带来源的上下文，在工具边界送达；空闲时保存上下文；排队时先入消息箱，启动后送达。它不会自动启动新的模型调用。`wait_agent` 读取尚未消费的消息，消息仍保留在模型上下文与通信记录中。消息箱和通信记录各保留最近 200 条；溢出后 `wait_agent` 会报告 `dropped` 数量。消息等待默认 30 秒、最多 60 秒，0 表示立即查看。

最终结果自动送给直属父代理。父代理提前结束而后代仍在运行时，Gateway 会等待后代，再启动父代理汇总；主代理同样会等待整个团队并汇总。整个过程属于同一轮任务，审批、停止与本轮变更检查保持有效。中断父代理会取消其正在执行及排队中的后代；继续父代理后可复用未关闭的子会话。

Plan 只能启动不含扩展的只读角色，只读子代理也只能继续委派只读角色。所有后代的业务工具与权限取祖先约束的交集；协作工具会自动安装，但自定义 `permissions` 的显式 deny 仍然有效。需要协作的自定义严格角色应明确允许相应协作工具。

浏览器侧栏显示完整路径、父代理链接、执行过程与通信记录，可沿父子关系或消息地址切换查看。协作过程作为主会话的自定义记录保存，重连可恢复。续跑依赖仍在内存中的子会话；后端重启、会话淘汰、切换主代理、资源重载或项目切换会释放子会话，保存的历史会标为已关闭。

每个主会话最多创建 64 个协作代理。并发设置统一限制所有团队及所有深度的正在执行任务；名额不足时按顺序排队。代理通过协作等待工具等待消息或结果时暂时让出名额，恢复执行前重新申请，因此并发为 1 时仍可运行嵌套委派。空闲、排队及协作等待中的代理不占执行名额。
